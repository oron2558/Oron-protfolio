02  How I work

Design Thinking, end to end.

Every product I build runs through the same five moves. I go wide to understand people, narrow down to the real problem, go wide again on ideas, then build and test until it works.

OronAI note
  • ChatGPT

    Part of my research flow: sorting interview notes into themes and ranking pain points, before I define the problem.

  • Claude Code

    This dot field is plain canvas code, written with Claude Code. No animation library.

01 / 05

  1. Empathize

    Listen before drawing anything.

    Interviews, field visits and competitor reviews, to understand how people work today and what actually hurts.

    • User interviews
    • Field research
    • Competitor review

  2. Define

    Name the real problem.

    Findings become journey maps and one sharp problem statement the whole team can build against.

    • Journey maps
    • Pain points
    • Problem statement

  3. Ideate

    Go wide, then choose.

    How Might We sessions, sketches and user flows. Many directions on the table before one is picked on purpose.

    • How Might We
    • Sketching
    • User flows

  4. Prototype

    Make it real, fast.

    Wireframes and UI in Figma, then working builds with AI tools like Claude Code and Lovable, not only mockups.

    • Wireframes
    • Figma UI
    • Built with AI

  5. Test

    Learn from real people.

    Usability tests, a real launch and real numbers. What I learn feeds straight back into the next round.

    • Usability tests
    • Launch and analytics
    • Iterate
